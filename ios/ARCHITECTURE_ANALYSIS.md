# تحليل بنية المشروع المرجعي — mizan-nabt

**تاريخ الدراسة:** 2026-08-16
**المستودع المدروس:** https://github.com/mjt-png/mizan-nabt (نسخة عند commit `6219023` — "Update index.html")
**طريقة الدراسة:** استنساخ كامل للمستودع (`git clone`) وقراءة كل ملف فيه سطرًا سطرًا (13 ملفًا، ~1800 سطر إجمالاً)، بالإضافة إلى فحص نصي لكل الملفات بحثًا عن أي استدعاء شبكة (`fetch`/`XMLHttpRequest`) أو منطق تحليل عروضي.

---

## ⚠️ الخلاصة الحاسمة أولًا

**مستودع `mjt-png/mizan-nabt` لا يحتوي على محرك تحليل عروضي إطلاقًا.** هو الموقع التسويقي/التعريفي الثابت (Static Website) الخاص بتطبيق "ميزان النبط"، مبني بـ HTML/CSS/JS بدون أي Backend، ومُستضاف على GitHub Pages. محرك الوزن الفعلي الذي يعمل داخل التطبيق الأصلي (iOS على App Store، وتطبيق أندرويد بمعرّف الحزمة `com.nabati.nabatimeter` على Google Play) **مغلق المصدر بالكامل** وغير منشور في أي مكان يمكن الوصول إليه قانونيًا.

هذا التحليل يوثّق بأمانة **ما هو موجود فعلًا** في المستودع مقابل كل بند طلبه المستخدم، ويوضح أين غاب المقابل.

---

## 1. Project Structure

```
mizan-nabt/
├── index.html      # الصفحة الرئيسية (تعريفية/تسويقية) — 557 سطر
├── app.js           # منطق الصفحة الرئيسية: تعبئة النصوص من data.js، الشريط المتحرك، تأثيرات ظهور عند التمرير
├── data.js          # "لوحة تحكم" المحتوى: كل النصوص، روابط المتجر، ودرس تعليمي واحد (٦ جذور)
├── style.css        # التصميم (متغيرات CSS للألوان + الثيم)
├── studio.html      # استوديو تسجيل صوتي (لصاحب الموقع فقط، غير مرتبط بأي زر ظاهر)
├── studio.js        # منطق تسجيل المايكروفون وتحويله MP3 عبر مكتبة lamejs، لإنتاج ملفات صوتية لدرس التشكيل
├── editor.js         # (كذا) محرر لتعديل جذور "الدرس" وتنزيل data.js محدّثًا — أداة محلية لصاحب الموقع
├── editor.html      # واجهة المحرر أعلاه
├── panel.html       # لوحة أدوات مقفلة بكلمة مرور (قفل ناعم من جهة العميل فقط)
├── lock.js          # منطق "القفل" (تجزئة كلمة مرور بسيطة تُقارن في المتصفح — ليست حماية حقيقية)
├── logo.png / favicon.png
└── README.md        # يشرح كيفية تعديل الموقع ونشره على GitHub Pages فقط
```

لا يوجد: `package.json`، لا Build tooling، لا Framework (لا React/Vue/إلخ)، لا مجلد `src/`، لا اختبارات، لا CI. المشروع صفحات ثابتة خام.

## 2. Entry Points

- **نقطة تشغيل الموقع:** `index.html` يُحمَّل مباشرة من GitHub Pages؛ يستدعي `data.js` ثم `app.js` اللذين يملآن القوالب بالنصوص التسويقية فقط.
- **لا يوجد** أي نقطة دخول لتحليل بيت شعري. لا حقل إدخال نص شعر، ولا زر "زن البيت" أو ما يعادله، في أي صفحة من صفحات الموقع.
- التطبيق الفعلي (الذي يقوم بالوزن) يُشار إليه فقط كرابط خارجي: `appStoreUrl` و`playStoreUrl` في `data.js`.

## 3. Poetry Engine

**غير موجود.** بحثت عن أي دالة تحليل، أي بنية بيانات بحور/طواريق، وأي استدعاء API خارجي (`grep` شامل لكل الملفات عن `fetch(` و`XMLHttpRequest` و`api.`) — لا نتائج البتة. لا يوجد محرك وزن، لا محليًا (Client-side) ولا عبر خدمة خارجية، في هذا المستودع.

## 4. Text Processing

لا يوجد معالجة نص عروضي. المعالجة النصية الوحيدة الموجودة هي تعبئة قوالب HTML بنصوص من `data.js` (`textContent`/`innerHTML` بسيطة)، ومنطق `editor.js` الذي يتعامل مع نص عادي (root/mushaddad/sakin/mutaharrik) كحقول نموذج (form fields) بدون أي تطبيع أو تحليل صوتي فعلي — هي فقط ٣ كلمات مُدخلة يدويًا لكل جذر (مثال: بحر → بَحّر/بَحْر/بَحَر) يكتبها صاحب الموقع بنفسه، وليست ناتجة عن خوارزمية.

## 5. Prosody

لا يوجد أي تحويل لبيت إلى صيغة عروضية. لا "كتابة عروضية"، لا تقطيع، لا رموز سبب/وتد.

## 6. Meter Detection

لا يوجد. لا قائمة بحور، لا دالة كشف بحر.

## 7. Tarooq Detection

لا يوجد. كلمة "طاروق" ترد فقط في نصوص تسويقية عامة مثل "أكثر من ١٠٠ طاروقٍ مع أمثلتها" — بلا أي بيانات أو قائمة فعلية مرفقة في الكود؛ الرقم "100+" ادّعاء تسويقي عن التطبيق المغلق، وليس بيانات في هذا المستودع.

## 8. Feet (التفعيلات)

لا يوجد.

## 9. Numeric Pattern

لا يوجد.

## 10. Rhyme (القافية والروي)

لا يوجد تحليل قافية. الدرس الوحيد في `data.js` (`lesson.roots`) يعلّم فرقًا صوتيًا مختلفًا تمامًا: نطق الحرف الأوسط من جذر ثلاثي في ٣ حالات — **مشدّد** (بَحّر) / **ساكن** (بَحْر) / **متحرّك** (بَحَر) — وهو محتوى تعليمي عن الشدة والسكون والحركة، له تسجيلات صوتية (MP3) تُنتَج يدويًا عبر `studio.html`، وليس تحليل قافية أو رويّ لبيت شعري.

## 11. Data

البيانات الوحيدة في المشروع هي كائن `SITE` داخل `data.js`: نصوص تسويقية، روابط، وست جذور (`bahr, nazm, qat, satr, dars, hukm`) لدرس الشدة/السكون/الحركة المذكور أعلاه. **لا توجد** بيانات بحور ولا طواريق ولا قواعد تقطيع في أي مكان بالمستودع.

## 12. Tests

**لا يوجد** أي اختبارات (لا وحدة ولا تكامل) في المستودع. لا مجلد tests، لا test runner، لا سطر اختبار واحد.

## أثر هذا الاكتشاف على المشروع

بناءً على توجيه المستخدم بعد عرض هذا الاكتشاف، تقرر: **بناء محرك وزن مستقل تمامًا** (وليس منقولًا أو "مستخرجًا" من مزودٍ لا وجود لكوده)، معتمدًا على علم العروض العربي الكلاسيكي والنبطي التقليدي (معرفة عامة/Public domain موثّقة في كتب العروض المعروفة، وليست ملكًا فكريًا خاصًا بـ mizan-nabt). راجع `PORTING_PLAN.md` للتفاصيل، و`POETRY_ENGINE.md` لتصميم المحرك الفعلي.

العناصر الوحيدة "المستوحاة" (وليست منسوخة) من الموقع المرجعي هي عناصر **تجربة استخدام عامة غير محمية بحقوق نشر** (ترتيب: إدخال بيت → زر "زن البيت" → عرض بحر/طاروق/تفعيلات/تقطيع)، وهذا نمط تفاعل عام شائع في كل تطبيقات العروض، وليس تعبيرًا إبداعيًا محميًا (Non-copyrightable functional UI pattern).
