# محرك التحليل العروضي (PoetryEngine)

## لماذا محرك مستقل؟

كما وثّقنا في `ARCHITECTURE_ANALYSIS.md`، لا يحتوي مستودع `mizan-nabt` المرجعي على أي محرك تحليل — فهو موقع تسويقي ثابت فقط. بقرار من مالك المشروع (بعد عرض هذا الاكتشاف)، بُني `PoetryEngine` **من الصفر** استنادًا إلى علم العروض العربي الكلاسيكي (نظام الخليل بن أحمد للسبب/الوتد/التفعيلة) مطبَّقًا على تسمية بحور الشعر النبطي التقليدية. هذه معرفة أكاديمية عامة (Public Domain)، وليست ملكية فكرية لأي تطبيق تجاري.

## المنهج

المحرك حزمة Swift Package مستقلة (`ios/PoetryEngine`)، Swift + Foundation فقط، بلا أي اعتماد على SwiftUI/UIKit — قابلة للاختبار عبر `swift test` وحدها، ولإعادة الاستخدام على أي منصة تدعم Swift.

خط الأنابيب (Pipeline) الكامل، من نص خام إلى `AnalysisResult`:

```
النص الخام
   │  TextNormalizer          (تنظيف: تطويل، مسافات، ترقيم، تجاهل غير العربي دون فشل)
   ▼
HemistichSplitter             (تقسيم البيت لشطرين: فاصل صريح، وإلا تخمين بعدد الكلمات)
   │
   ▼  لكل شطر
ProsodicTranscriber            (الكتابة العروضية: شدة/سكون/تنوين/مد/همزة وصل/لام شمسية-قمرية/تاء مربوطة/لفظ الجلالة)
   │
   ├─▶ NumericPatternBuilder   (نمط 1/0 لكل حرف: 1=متحرك، 0=ساكن)
   ├─▶ SyllableSegmenter       (تجميع لمقاطع سبب/وتد/فاصلة)
   │
   ▼
MeterMatcher                   (مطابقة النمط الرقمي بكل (بحر، طاروق) في meters.json عبر تشابه ليفنشتاين)
   │
   ├─▶ FootSegmenter           (تقطيع النمط المطابَق إلى تفعيلات مسمّاة)
   └─▶ RhymeAnalyzer            (حرف الروي: مقارنة نهاية الشطرين)
   ▼
AnalysisResult
```

## قواعد التحويل العروضي المطبَّقة

كل قاعدة أدناه مطبَّقة في `ProsodicTranscriber.swift` وموثَّقة هناك بتعليق مختصر عند كل حالة:

| الحالة | القاعدة المطبَّقة |
|---|---|
| الشدة (ّ) | تكرار الحرف: الأول ساكن (إدغام)، الثاني بحركته (أو التنوين إن وُجد). |
| السكون (ْ) | وحدة ساكنة مباشرة. |
| التنوين (ً ٍ ٌ) | حركة قصيرة + نون ساكنة مضافة؛ تُهمَل الألف الفارقة الكتابية بعد تنوين الفتح (مثل "كتابًا"). |
| المد بالألف | ألف بلا تشكيل بعد فتحة → وحدة ساكنة ممتدة. |
| المد بالواو | واو بلا تشكيل بعد ضمة → وحدة ساكنة ممتدة؛ وإلا واو صامتة عادية بحركتها. |
| المد بالياء | ياء بلا تشكيل بعد كسرة → وحدة ساكنة ممتدة؛ وإلا ياء صامتة عادية بحركتها. |
| الهمزات | آ = همزة مفتوحة + ألف مد (وحدتان)؛ أ/إ تُعامَلان كحرف عادي بحركته المكتوبة. |
| اللام الشمسية | تُدغم (لا تُكتب عروضيًا) ويُضعَّف الحرف التالي (شدة)، مع الكشف التلقائي للحروف الشمسية الأربعة عشر. |
| اللام القمرية | تبقى ساكنة كما هي. |
| همزة الوصل ("أل" التعريف) | تُنطق فتحًا عند الابتداء المطلق بالبيت فقط، وتُحذف عروضيًا في الوصل (بعد كلام متصل أو بادئة و/ف/ب/ك/ل). |
| تاء التأنيث المربوطة | هاء ساكنة عند نهاية الشطر (وقف)؛ تاء متحركة إن كانت وسط الشطر (وصل). |
| لفظ الجلالة | حالة خاصة صريحة لـ"الله" وصوره المتصلة (والله/فالله/بالله/كالله/تالله/لله) لأن نطقها يتضمن مدًّا غير مكتوب بعد اللام المشددة. |
| الكلمات المتجاورة | قراءة متصلة (وصل) بين كلمات الشطر الواحد؛ لا فواصل صامتة مُقحَمة. |
| علامات الترقيم/المسافات | تُزال قبل التحليل ولا تؤثر على النتيجة. |
| نص غير عربي (أرقام/إيموجي/لاتيني) | يُتجاهَل تمامًا دون تعطّل المحرك؛ يُسجَّل تنبيه `inputContainsNonArabicCharacters`. |
| غياب التشكيل | افتراض فتحة قصيرة كقيمة افتراضية موثَّقة (لا يوجد تشكيل تلقائي كامل)؛ ينعكس في تراجع `confidence` وتنبيه `missingDiacriticsReducesAccuracy`. |

## النمط الرقمي والمقاطع

يُحسب النمط الرقمي حرفًا حرفًا (1 = متحرك، 0 = ساكن) عبر `NumericPatternBuilder`. تُبنى تفعيلات قاعدة البيانات نفسها (`meters.json`) بنفس هذا المحرك من تشكيلها الكامل (مثل `مُسْتَفْعِلُنْ`)، بدل حفظ سلاسل أرقام يدويًا — هذا يضمن اتساق التعريف: أي تغيير مستقبلي في قواعد التحويل ينعكس تلقائيًا على أنماط قاعدة البيانات أيضًا، بلا احتمال تعارض بين الاثنين.

يُجزَّأ النمط إلى مقاطع كلاسيكية (`SyllableSegmenter`) بخوارزمية جشعة تفضّل أطول نمط معروف عند كل موضع: فاصلة كبرى (11110) ← فاصلة صغرى (1110) ← وتد مجموع (110) ← وتد مفروق (101) ← سبب ثقيل (11) ← سبب خفيف (10).

## قاعدة بيانات البحور والطواريق

كتالوج ابتدائي في `Sources/PoetryEngine/Resources/meters.json` يضم **٦ بحور نبطية** معروفة عمومًا (الهجيني، المسحوب، السامري، الهلالي، الصخري، الحدائي) بإجمالي **١١ طاروقًا**. هذا **كتالوج بداية قابل للتوسّع**، وليس ادعاءً بالشمول أو مطابقة أي قاعدة بيانات تجارية (راجع `LICENSE_NOTES.md`). إضافة بحر أو طاروق جديد لا تتطلب تعديل كود المحرك — فقط إضافة إدخال JSON جديد بنفس البنية.

**توصية:** مراجعة هذه القائمة من متخصص في العروض النبطي قبل أي إطلاق عام، وتوسيعها تدريجيًا.

## المطابقة والثقة (Confidence)

- يُقارَن النمط الرقمي المستخرَج بنمط كل (بحر، طاروق) عبر تشابه ليفنشتاين معياري (0...1).
- تشابه **1.0** = تطابق تام. تشابه **≥ 0.85** = يُعدّ "موزونًا" (زحاف غير مسجَّل صراحة كطاروق مستقل). أقل من ذلك = "غير موزون"، مع إظهار أقرب ٣ بحور كـ`alternatives`.
- إن أمكن تقسيم البيت لشطرين، يُطابَق كل شطر منفردًا؛ الثقة النهائية تعتمد التطابق الأضعف بينهما (تحفّظ متعمَّد بدل التفاؤل الزائد).
- `confidence` = مزيج مرجّح من (نسبة التشكيل المُدخَل، درجة تطابق النمط)، مع خصم عند غياب فاصل شطرين صريح أو وجود محتوى غير عربي.

## القافية والروي

يُقارَن حرف الروي (آخر صامت مسموع، بتجاوز حروف المد الساكنة الصرفة) بين الشطرين. متاح فقط عند نجاح تقسيم البيت لشطرين (`rhyme == nil` إن تعذّر ذلك).

## القيود الموثَّقة

- **بلا تشكيل تلقائي كامل:** الدقة القصوى تتطلب تشكيلًا صريحًا من المستخدم؛ بدونه يطبّق المحرك افتراضات بسيطة موثَّقة (فتحة افتراضية)، وتنخفض `confidence` تبعًا لذلك.
- **همزة الوصل:** قائمة استثناءات محدودة (أفعال أمر ثلاثية، أسماء مثل ابن/اسم) غير مطبَّقة بالكامل بعد؛ الأولوية لقاعدة "أل" التعريف الأكثر شيوعًا.
- **تقسيم الشطرين:** يعتمد على فاصل صريح إن وُجد (مسافات متعددة، "/"، "|"...)، وإلا تخمين بعدد الكلمات — قد لا يطابق التقسيم الفعلي لكل الحالات.
- **كتالوج البحور:** ٦ بحور و١١ طاروقًا كبداية، وليس قائمة شاملة لكل بحور وطواريق الشعر النبطي (لا توجد قائمة مصدرية مفتوحة يمكن استخراجها منها، كما وضّحنا في `ARCHITECTURE_ANALYSIS.md`).
