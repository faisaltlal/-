# التشغيل من تابلت أو آيفون — بلا أي جهاز

كل ما في هذا الملف يعمل من متصفح فقط. لا Xcode، ولا Mac، ولا محاكي،
ولا Appetize.

---

## ١. تجربة المحرك — الطريقة اليومية

صفحة تعمل كاملةً داخل متصفحك. لا خادم، ولا شبكة، ولا يُرسَل نصّك إلى
أي مكان.

### بعد الدمج في `main`

```
https://faisaltlal.github.io/-/nabati/web/
```

يعمل تلقائيًا: مسار النشر القائم يرفع جذر المستودع كما هو، فالصفحة
الجديدة تُنشر معه دون تعديل. **صفحة «مشراف» تبقى على جذر الموقع كما
هي، لم تُمسّ.**

> إن ظهر خطأ 404 فالسبب أن Pages لم يُفعَّل بعد:
> **Settings ← Pages ← Source ← GitHub Actions** — خطوة يدوية لمرة واحدة.

### قبل الدمج — لمعاينة الفرع مباشرة

```
https://raw.githack.com/faisaltlal/-/claude/nabati-poetry-engine-t6pksi/nabati/web/index.html
```

يخدم `raw.githack.com` ملفات الفرع بأنواع MIME صحيحة، فتعمل وحدات
JavaScript كما هي. مفيد لرؤية تعديل قبل دمجه.

### أضفها إلى شاشة آيفونك

Safari ← زر المشاركة ← **إضافة إلى الشاشة الرئيسية**. تصير أيقونة
تفتح المحرك مباشرة.

### ما في الصفحة

| التبويب | ماذا يفعل |
|---|---|
| **تحليل بيت** | البحر، الدرجة، الثقة، التفعيلات، التقطيع، النمط الرقمي، موضع الكسر، البدائل |
| **تحليل قصيدة** | بيت في كل سطر ← الوزن الغالب والتوزيع والأبيات الخارجة |
| **تدريب** | اختر بحرًا ومستوى صعوبة واكتب بيتًا، فيقول لك أين اختلّ |
| **البحور** | القاعدة كاملة، ومنها المعطَّل وسبب تعطيله |
| **ما يحتاج تحقّقًا** | كل قاعدة لم تُثبَّت وما ينقص لإثباتها |

**وضع التتبّع**: صندوق في الصفحة، أو أضف `?debug=1` إلى الرابط. يعرض
كل مرحلة: الأصل ← المطبَّع ← العروضي ← الوحدات ← المقاطع ← النمط
الرقمي ← المرشّحين ← المطابقة ← الدرجة. لا يلزم لتشغيله شيء.

## ٢. تشغيل الاختبارات — من الهاتف

### الطريقة الأسهل: زرّ في GitHub

1. افتح المستودع في المتصفح
2. **Actions**
3. **محرك العروض النبطي** من القائمة اليمنى
4. **Run workflow** ← اختر الفرع ← **Run workflow**

بعد دقيقة تقريبًا: ✅ أو ❌. اضغط على أي مهمّة لترى أي اختبار فشل ولماذا.

الاختبارات تعمل تلقائيًا أيضًا عند كل دفع يمسّ `nabati/`.

### ماذا يُشغَّل

| المهمّة | ماذا تفحص |
|---|---|
| جافاسكربت | تطابق البيانات المولَّدة مع مصدرها، ثم كل الاختبارات، ثم صحة كل ملفات JSON |
| Swift | بناء الحزمة واختباراتها — تقرأ نفس `golden_cases.json` |

## ٣. تعديل البيانات — من الهاتف

أغلب التطوير المتوقَّع بعد الآن تعديل بيانات لا كود:

1. افتح الملف على GitHub (`nabati/data/meters.json` مثلًا)
2. اضغط أيقونة القلم ✏️
3. عدّل، ثم **Commit changes**
4. **Actions** ← انتظر النتيجة

⚠️ **بعد تعديل أي ملف في `data/`** يجب إعادة توليد النسخ:

```
node nabati/tools/bundle-data.js
```

من الهاتف لا يمكنك تشغيل `node`. فافعل واحدًا من اثنين:

- **الأسهل**: عدّل نفس القيمة في `nabati/engine/js/data.generated.js` يدويًا،
- **الأنظف**: عدّل `data/` فقط، ثم اطلب مني إعادة التوليد في جلسة تالية.

فحص CI سيفشل ويخبرك صراحةً بأي نسخة تأخّرت، فلن يمرّ الانحراف بصمت.

## ٤. تحرير الكود — من الهاتف

### أ. GitHub.dev (الأسرع، بلا إعداد)

افتح المستودع واضغط **`.`** على لوحة المفاتيح — أو بدّل العنوان:

```
github.com/faisaltlal/-   ←   github.dev/faisaltlal/-
```

يفتح محرّر VS Code كامل في المتصفح. يحرّر ويلتزم ويدفع. **لا يشغّل
أوامر** — لتشغيل الاختبارات استعمل زرّ Actions.

### ب. Codespaces (بيئة كاملة تشغّل الأوامر)

**Code ← Codespaces ← Create codespace**

طرفية حقيقية في المتصفح:

```bash
node nabati/tools/bundle-data.js   # إعادة توليد نسخ البيانات
node nabati/tests/run.js           # الاختبارات
python3 -m http.server 8000        # ثم افتح المنفذ لمعاينة الصفحة
```

تنبيه: Codespaces لها حصّة ساعات مجانية شهرية، **وتُحاسَب بالساعة وهي
تعمل**. أوقفها إذا لم تستعملها. للتعديلات الصغيرة، `github.dev` + زرّ
Actions أرخص وأسرع.

## ٥. ما لا يعمل من متصفح — وماذا نفعل بدله

| المطلوب | متاح من متصفح؟ | البديل |
|---|---|---|
| بناء حزمة Swift واختبارها | ✅ | GitHub Actions (لينكس) |
| بناء تطبيق iOS | ❌ | يحتاج Xcode على macOS — وهو PHASE 7، آخر مرحلة |
| تشغيل محاكي iOS | ❌ | لا حاجة إليه قبل PHASE 7 |
| تجربة المحرك | ✅ | صفحة الويب |

**لهذا بُني المحرك حزمةً مستقلة تمامًا عن الواجهة.** كل ما في PHASE ١
إلى ٦ يُطوَّر ويُختبَر ويُجرَّب من متصفحك. ولن تحتاج Mac إلا عند تغليف
النتيجة في تطبيق، بعد أن يكون المحرك قد أثبت نفسه.

## ٦. سير عمل مقترح

1. جرّب أبياتًا في الصفحة من تابلتك.
2. حين تجد نتيجة خاطئة، خذ البيت وأضفه إلى `golden_cases.json` مع
   النتيجة الصحيحة (من `github.dev`).
3. شغّل Actions — سيفشل الاختبار الجديد، وهذا هو المطلوب: صار الخطأ
   مسجَّلًا لا منسيًّا.
4. أصلح القاعدة (غالبًا في `data/`)، وأعد التشغيل حتى يخضرّ.

هكذا يتحسّن المحرك بأبياتك أنت، ولا ترجع مشكلة أُصلحت مرة.
