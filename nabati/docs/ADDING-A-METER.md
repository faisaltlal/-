# كيف تضيف بحرًا جديدًا بنفسك

هذا شرط أساسي في المواصفة (البند ٣٠)، لا تحسينًا لاحقًا: **إضافة بحر
لا تتطلّب تعديل كود المحرك إطلاقًا** — لا المطابق، ولا المُقيِّم، ولا
المُقطِّع.

كل ما تحتاجه تحرير ملفَّي بيانات وتشغيل الاختبارات.

---

## الحالة الأولى: البحر يتركّب من تفعيلات موجودة

هذه أغلب الحالات. التفعيلات المتاحة الآن:

| المعرّف | التفعيلة | النمط |
|---|---|---|
| `faulun` | فعولن | `SLL` |
| `failun` | فاعلن | `LSL` |
| `mafailun` | مفاعيلن | `SLLL` |
| `mustafilun` | مستفعلن | `LLSL` |
| `failatun` | فاعلاتن | `LSLL` |
| `failun_short` | فعلن (فَعِلُنْ) | `SSL` |
| `faalun` | فعلن (فَعْلُنْ) | `LL` |
| `mufaalatun` | مفاعلتن | `SLSSL` |

### الخطوة ١ — افتح `nabati/data/meters.json`

### الخطوة ٢ — أضف كائنًا في مصفوفة `meters`

مثال: لنفترض أن بحر **السامري** تفعيلاته
`فاعلاتن | فاعلاتن | فعولن`:

```json
{
  "id": "al_samri",
  "name": "السامري",
  "aliases": [],
  "enabled": true,
  "sourceIndex": 14,
  "sourceQuote": "فاعلاتن | فاعلاتن | فعولن",
  "feet": ["failatun", "failatun", "faulun"],
  "expectedSyllableCount": 11,
  "status": "OK"
}
```

الحقول:

| الحقل | إلزامي | معناه |
|---|---|---|
| `id` | نعم | معرّف لاتيني فريد، لا يتغيّر بعد ذلك |
| `name` | نعم | الاسم العربي كما يُعرض |
| `aliases` | نعم (ولو `[]`) | أسماء أخرى للبحر نفسه — تُستعمل في البحث |
| `enabled` | نعم | `false` يستبعده من المطابقة مع بقائه مسجَّلًا |
| `sourceQuote` | نعم | التفعيلات كما وردت في مصدرك حرفيًا |
| `feet` | نعم | معرّفات التفعيلات **لشطر واحد** لا لبيت كامل |
| `expectedSyllableCount` | نعم | مجموع مقاطع التفعيلات — قيمة تحقّق |
| `status` | نعم | `OK` أو `NEEDS_VALIDATION` |

**احسب `expectedSyllableCount` بجمع أطوال الأنماط**: فاعلاتن ٤ +
فاعلاتن ٤ + فعولن ٣ = ١١. إن أخطأت فشلت الاختبارات وأخبرتك بالرقمين —
وهذا مقصود، فهو يمنع تعريفًا يناقض نفسه.

### الخطوة ٣ — أضف حالة تحقّق في `golden_cases.json`

في مصفوفة `verses`:

```json
{
  "id": "samri_1",
  "input": "بيت حقيقي من السامري مشكولًا",
  "expectedMeter": "al_samri",
  "expectedConfidenceRange": [0.9, 1.0],
  "expectedTafaeel": ["فاعلاتن", "فاعلاتن", "فعولن"],
  "expectedBrokenFeet": [],
  "source": "app"
}
```

**اكتب البيت مشكولًا.** غير المشكول يقبل قراءات كثيرة، فالحالة تصير
ضعيفة الدلالة (انظر `PROSODY.md` §٤).

### الخطوة ٤ — شغّل الاختبارات

```
node nabati/tools/bundle-data.js    # يحدّث النسخ المولَّدة
node nabati/tests/run.js
```

من التابلت: ادفع التعديل، ثم **Actions ← محرك العروض النبطي ← Run
workflow**. الاختبارات المشتقّة من البيانات تلتقط بحرك الجديد تلقائيًا:

- «كل بحر يطابق نمطه هو مطابقة تامة»
- «كل بحر يتصدّر ترتيب نمطه هو»
- «كل بحر مفعَّل له تفعيلات ونمط غير فارغ»

لم تكتب اختبارًا واحدًا، ومع ذلك صار البحر مغطّى.

## الحالة الثانية: البحر يحتاج تفعيلة غير موجودة

### الخطوة ١ — أضفها في `nabati/data/tafaeel.json`

عليك حساب حقلين. الطريقة:

**١. انطق التفعيلة مشكولةً وقسّمها مقاطع.**

مثال `مُتَفَاعِلُنْ`: مُ + تَ + فَا + عِ + لُنْ

**٢. اكتب كمّية كل مقطع:**

| المقطع | التركيب | الكمّية |
|---|---|---|
| مُ | صامت + حركة قصيرة | `S` |
| تَ | صامت + حركة قصيرة | `S` |
| فَا | صامت + حركة طويلة | `L` |
| عِ | صامت + حركة قصيرة | `S` |
| لُنْ | صامت + قصيرة + ساكن | `L` |

فالنمط `["S","S","L","S","L"]`.

**٣. اشتقّ النمط الحرفي**: كل `S` ← `1`، وكل `L` ← `10`، وكل `X` ← `100`.

`1` + `1` + `10` + `1` + `10` = `"1110110"`

**تحقّق**: عدد الأحرف يجب أن يساوي عدد حروف التفعيلة مشكولةً.
`مُتَفَاعِلُنْ` سبعة أحرف، و`1110110` سبعة رموز. ✓

```json
{
  "id": "mutafailun",
  "plain": "متفاعلن",
  "vocalized": "مُتَفَاعِلُنْ",
  "syllables": ["S", "S", "L", "S", "L"],
  "khalilLetters": "1110110",
  "components": ["فاصلة صغرى", "وتد مجموع"],
  "status": "STANDARD"
}
```

إن اختلف الحقلان أفشلت الاختبارات البناءَ وأرَتْك الرقمين. لا يمرّ
تعريف متناقض.

### الخطوة ٢ — أضف صورها في `variations.json`

**الحدّ الأدنى الصورة السالمة:**

```json
"mutafailun": [
  { "id": "salim", "name": "سالم", "result": "مُتَفَاعِلُنْ",
    "syllables": ["S","S","L","S","L"], "kind": "salim",
    "scope": "any", "severity": 1 }
]
```

ثم أضف ما تعرفه من زحافات وعلل:

| الحقل | القيم | متى |
|---|---|---|
| `kind` | `zihaf` | تغيير في الأسباب، جائز في الحشو |
| | `illa` | لازمة في العروض والضرب وحدهما |
| | `ambiguous_reading` | قراءتان مشروعتان لرسم واحد — ليست عيبًا |
| `scope` | `any` | الحشو والعروض والضرب |
| | `arud_darb` | العروض والضرب فقط |
| `severity` | `1` | شائع |
| | `2` | نادر أو ثقيل — كلفته أعلى |

**لا تخترع زحافات.** التفعيلة بصورتها السالمة وحدها تعمل تمامًا؛
غاية الأمر أن البحر يكون أشدّ صرامة. وهذا بالضبط حال `مفاعلاتن` في
الصخري: تفعيلتها نفسها غير مثبتة، فاختراع زحافات لها يضاعف الخطأ.

## إن كان تعريف البحر غير مؤكَّد

لا تفعّله. سجّله بـ `enabled: false` وبيّن ما ينقص:

```json
{
  "id": "al_something",
  "name": "بحر ما",
  "enabled": false,
  "feet": null,
  "status": "NEEDS_VALIDATION",
  "derivation": {
    "why_not_implemented": "المصدر يصفه بكذا، وهو وصف غير قابل للتنفيذ",
    "candidates": [
      { "id": "reading_a", "feet": ["..."], "plausibility": "الأرجح لأن…" },
      { "id": "reading_b", "feet": ["..."], "plausibility": "ممكن لكن…" }
    ],
    "resolvedBy": "بيت واحد حقيقي مع تقطيعه"
  }
}
```

يظهر البحر عندئذ في تبويب «ما يحتاج تحقّقًا» في الصفحة وفي
`engine.openQuestions()`، ولا يشوّش المطابقة. هذا بالضبط حال
**الهلالي الطويل** — انظر تعريفه في `meters.json` نموذجًا كاملًا.

## ما الذي لن تحتاج لمسّه أبدًا

`meterMatcher.js` — `footMatcher.js` — `scorer.js` — `syllableDag.js` —
`phonemizer.js` — `registry.js` — أي ملف Swift.

إن وجدت نفسك مضطرًّا لتعديل أحدها لإضافة بحر، فتلك ثغرة في التصميم لا
في استعمالك — أخبرني بها.

## المراجعة الأخيرة قبل الدفع

- [ ] `id` فريد لم يُستعمل من قبل
- [ ] `feet` لشطر واحد لا لبيت كامل
- [ ] `expectedSyllableCount` = مجموع أطوال أنماط التفعيلات
- [ ] كل معرّف في `feet` موجود في `tafaeel.json`
- [ ] لكل تفعيلة مدخل في `variations.json` ولو بالسالمة وحدها
- [ ] حالة `golden` واحدة على الأقل، ببيت **مشكول**
- [ ] `node nabati/tools/bundle-data.js` ثم `node nabati/tests/run.js`
